ГРАММАТИКА FUNNY (HW2, ветка LL(1), рекурсивный спуск)
=======================================================

Нотация: EBNF.  'x' — терминал (токен лексера), X? — необязательно,
X* — ноль и более, X+ — один и более, | — альтернатива, (...) — группировка.
IDENT, INT — токены лексера; ключевые слова — зарезервированы.

------------------------------------------------------------------------
1. Синтаксис
------------------------------------------------------------------------

program     = function+ EOF

function    = 'function' IDENT '(' params? ')'
              ( 'returns' returns )?
              clause*
              block

clause      = 'uses' IDENT ( ',' IDENT )*
            | 'requires' expr
            | 'ensures' expr            (* clause* — в любом порядке и количестве *)

params      = param ( ',' param )*
param       = IDENT ( ':' type )?       (* тип параметра можно опустить *)
returns     = type                      (* анонимный результат *)
            | '(' params ')'            (* именованные результаты, >= 1 *)
type        = ( 'int' | 'bool' ) ( '[' ']' )?

block       = '{' stmt* '}'

stmt        = block
            | 'if' '(' expr ')' stmt ( 'else' stmt )?
            | 'while' '(' expr ')' ( 'invariant' expr )* stmt
            | 'assert' expr ';'
            | 'assume' expr ';'
            | 'return' expr? ';'
            | type IDENT ( '=' expr )? ';'                 (* объявление *)
            | IDENT '=' expr ';'                           (* присваивание *)
            | IDENT '[' expr ']' '=' expr ';'              (* обновление массива, см. п. 3 *)
            | IDENT '(' args? ')' ';'                      (* вызов как оператор *)

args        = expr ( ',' expr )*

------------------------------------------------------------------------
2. Выражения: приоритеты и ассоциативность (от низшего к высшему)
------------------------------------------------------------------------

  уровень | операторы                 | ассоциативность
  --------+---------------------------+--------------------------------
     1    | or                        | левая
     2    | and                       | левая
     3    | not (префиксный)          | правая (not not a = not (not a))
     4    | == != < <= > >=           | НЕассоциативные (a < b < c — ошибка)
     5    | + -  (бинарные)           | левая
     6    | * /                       | левая
     7    | - (унарный)               | правая
     8    | a[i], f(...)  (постфикс)  | левая

  expr    = or_
  or_     = and_ ( 'or' and_ )*
  and_    = not_ ( 'and' not_ )*
  not_    = 'not' not_ | cmp
  cmp     = add ( ( '==' | '!=' | '<' | '<=' | '>' | '>=' ) add )?
  add     = mul ( ( '+' | '-' ) mul )*
  mul     = unary ( ( '*' | '/' ) unary )*
  unary   = '-' unary | postfix
  postfix = primary ( '[' expr ']' )*
  primary = INT | 'true' | 'false'
          | IDENT ( '(' args? ')' )?
          | 'length' '(' args? ')'
          | '(' expr ')'

Левая рекурсия устранена циклами (a = b (op b)*): дерево всё равно строится
левоассоциативно.

------------------------------------------------------------------------
3. Сахар для массивов
------------------------------------------------------------------------

  a[i] = e;   разбирается как   a = store(a, i, e)

в AST: Assign(target='a', sugar=True, value=Store(array=Var a, index=i, value=e)).
Обращение a[i] — узел Index(array, index).

------------------------------------------------------------------------
4. Почему грамматика LL(1) — все нетривиальные точки выбора
------------------------------------------------------------------------

  Точка выбора              | FIRST-множества / довод
  --------------------------+----------------------------------------------------
  program: function или EOF | {function} / {EOF}
  clause*                   | {uses, requires, ensures} не пересекается с {'{'}
  returns                   | {'('} / {int, bool}
  type: суффикс '[' ']'     | '[' не входит в FOLLOW(type) = {',', ')', IDENT,
                            |  uses, requires, ensures, '{'}
  stmt                      | {'{'}, {if}, {while}, {assert}, {assume}, {return},
                            |  {int, bool}, {IDENT} — попарно не пересекаются
  stmt, ветка IDENT         | левая факторизация: IDENT ( '=' ... | '[' ... | '(' ... );
                            |  выбор по 1 токену ПОСЛЕ IDENT. Реализовано через
                            |  peek(1) — это эквивалентно факторизованной грамматике
                            |  stmt = IDENT stmt_rest, т.е. LL(1)
  primary, ветка IDENT      | IDENT ( '(' ... )?  — '(' не входит в FOLLOW(primary)
                            |  (выражение не может быть за ним сразу)
  while: invariant*         | 'invariant' не может продолжать expr; FIRST(stmt) не
                            |  содержит операторов выражения ('[' — постфикс — не
                            |  начинает ни один оператор)
  return expr? ';'          | {';'} / FIRST(expr)
  if ... else?              | КОНФЛИКТ «висячий else»: 'else' ∈ FOLLOW(stmt) и
                            |  ∈ FIRST('else' stmt). Разрешён жадно: else
                            |  относится к ближайшему if (стандартный приём
                            |  рекурсивного спуска).

------------------------------------------------------------------------
5. Обработка ошибок (режим паники)
------------------------------------------------------------------------

  * Ошибка внутри оператора: сообщение с позицией, затем пропуск токенов до
    границы оператора — ';' (потребляется), либо перед '}' / 'function' /
    токеном начала оператора ('{', if, while, assert, assume, return, int, bool).
  * Ошибка в заголовке функции: пропуск до '{' (тело всё равно разбирается),
    'function' или конца файла.
  * Мусор между функциями: одно сообщение, пропуск до следующего 'function'.
  * Незакрытая '(' '[' '{' — сообщение содержит позицию открывающей скобки.
  * Пропущенная ';' — позиция сразу после предыдущего токена.
  * Повторные сообщения на одном и том же токене подавляются.
  * Каждый цикл разбора либо потребляет токен, либо завершается ->
    парсер не зацикливается (проверено фаззинг-тестами).

------------------------------------------------------------------------
6. Отклонения/допущения (см. также README)
------------------------------------------------------------------------

  Файл docs/funny.ru.md и презентации P03/P04 при подготовке были недоступны,
  поэтому грамматика построена по тексту задания HW2. Всё, что взято
  «по умолчанию», перечислено ниже — сверьте с эталонной грамматикой:

  1. Тип параметра необязателен (`function fib(n) returns int`).
  2. returns: либо один тип, либо список именованных результатов.
  3. Предусловия/постусловия: requires/ensures — выражения, допускается любое
     число (ноль = «пустой» контракт); uses — список имён.
  4. Инвариант цикла: `while (c) invariant e1 invariant e2 body`.
  5. Логические связки словами: and / or / not; константы true / false.
  6. Деления по модулю, кванторов (forall/exists), импликации нет.
  7. Многомерные обновления a[i][j] = e не поддержаны.
  8. Положение узла Binary/Unary — позиция оператора, остальных узлов —
     позиция первого токена.
