2. Идея рекурсивного спуска (LL(1))

Каждому нетерминалу грамматики соответствует функция parse_X(). Она смотрит на один текущий токен (lookahead, self.peek()) и по нему однозначно выбирает ветку правила — в этом смысл «LL(1)»: чтение слева направо, левый вывод, один токен просмотра. Функция «съедает» токены (expect/advance) и вызывает функции вложенных нетерминалов — отсюда стек вызовов в плеере. Когда правило разобрано, функция возвращает узел AST.

def parse_stmt(self):
    t = self.peek()                       # lookahead
    if t.name == "KW_IF":                 # FIRST(if-оператора) = { 'if' }
        self.advance()                    # съели 'if'
        lp = self.expect("LPAREN")        # ожидаем '('
        cond = self.parse_expr()          # вложенное правило → новый кадр стека
        self.expect("RPAREN", opener=lp)
        then = self.parse_stmt()          # рекурсия
        els = self.parse_stmt() if self.match("KW_ELSE") else None
        return If(cond, then, els, ...)   # узел AST достраивается на выходе

Чем выше приоритет — тем глубже функция в стеке. Поэтому в 1 + 2 * 3 узел * строится глубже и раньше узла +. Откройте сценарий «2. Приоритеты» и смотрите на стек. Левая ассоциативность: left = parse_mul(); while at(+,−): left = Binary(op, left, parse_mul()) — каждая новая операция «обёртывает» накопленное слева.

5. Режим паники (обработка ошибок)

  1. Парсер находит несоответствие и делает raise ParseError(сообщение, индекс токена) — стек вызовов «сворачивается» вверх.
  2. Исключение ловит ближайший обработчик: parse_block (ошибка в операторе), parse_function (в заголовке). report() записывает диагностику строка:столбец и подавляет повторы на том же токене.
  3. Синхронизация — выбрасываем токены, пока не дойдём до «безопасной границы»: ; (его тоже съедаем), перед }, function или токеном начала оператора. Для заголовка — до {.
  4. Сломанный оператор отбрасывается, разбор продолжается со следующего — так находятся несколько независимых ошибок за один проход.
  5. Гарантия завершения: каждая итерация цикла либо съедает токен, либо выходит из цикла (если после ошибки указатель не сдвинулся — принудительный advance()). Поэтому парсер не зацикливается на любом входе.

6. AST

Узлы — dataclass'ы с позицией line:col (у бинарных операций — позиция оператора). Дерево строится снизу вверх: листья (числа, имена) возвращаются раньше, чем собираются родители — в плеере это видно по «загоранию» узлов. a[i] = e разворачивается в Assign(a, Store(a, i, e), sugar=True).

7. Как читать плеер

  • ▶ вход в правило — в стек добавился кадр parse_X, показан выбор ветки по lookahead.
  • ✓ съедаем токен — указатель сдвинулся.
  • ◀ выход — правило вернуло узел AST.
  • ‼ ошибка / ⌫ пропуск — режим паники.
  • ⤳ синхронизация — выбрали точку восстановления.

Клавиши: ←/→ шаг, пробел пуск/пауза, Home/End начало/конец.

Алфавит ДКА: символов; всё за его пределами (включая весь не-ASCII) уходит в ловушку → лексическая ошибка. Для каждого токена парсер получает name, value, line, col; пробелы и комментарии лексер пропускает (skip). Конфликты одинаковой длины решает порядок в списке (ключевые слова раньше IDENT), разной длины — maximal munch (самое длинное совпадение).

Во вкладке плеера кликните по любому токену — увидите путь ДКА по его символам и причину остановки (следующий символ ведёт в ловушку).
