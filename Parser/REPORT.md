# Отчёт — HW2. Парсер Funny (LL(1))

## 1. Выбор ветки
LL(1), рекурсивный спуск: по функции на нетерминал, выражения — по функции на
уровень приоритета. Ошибки — режим паники. Лексер HW1 подключён напрямую
(`build_lexer().scan`), токены несут `line`/`col`.

## 2. Грамматика
Финальный вид — `grammar.txt`. Левая рекурсия в выражениях устранена циклами;
ветка `IDENT` в операторе левофакторизована (выбор по токену после `IDENT`).
Единственный LL(1)-конфликт — «висячий else» — разрешён жадно (else к
ближайшему if).

Приоритеты (низший → высший): `or` < `and` < `not` < сравнения (неассоциативные)
< `+ -` < `* /` < унарный `-` < `a[i]`, `f(...)`. Бинарные операторы левоассоциативны.

## 3. AST
Узлы-dataclass'ы, вывод деревом и JSON (`"node"`, поля, `"pos"`). `a[i] = e`
разворачивается в `Assign(a, Store(a, i, e))` — функциональное обновление.

## 4. Ошибки
Формат `строка:столбец: ошибка: сообщение`. Для незакрытых скобок указывается
позиция открывающей; для пропущенной `;` — позиция сразу после предыдущего
токена. Синхронизация: до `;`, `}`, `function` или токена начала оператора.
Повторы на одном токене подавляются; лексические ошибки включаются в тот же
список. Завершение гарантировано (прогресс на каждой итерации).

## 5. Тесты (267, все проходят)
* позитивные: 5 программ со снимками AST, конструкции языка, массивы,
  20 случаев приоритетов/ассоциативности, позиции узлов, JSON/tree-вывод;
* негативные (25): пустой ввод, незакрытые `( [ {`, лишние токены, неверный
  оператор, пропущенная `;`, `else` без `if`, нет тела/имени, мусор, не-ASCII;
* восстановление: после ошибки разбираются следующие операторы и функции;
* устойчивость: 1500 случайных наборов токенов, 600 мутаций верной программы,
  патологические входы, программа из 5000 операторов.

## 6. Допущения
Список — в конце `grammar.txt` (тип параметра необязателен, форма
`invariant`, `and/or/not`, и т.д.). Эталонная грамматика Funny и замечания из
презентации не были доступны — их нужно сверить.
