# HW1 — Лексер языка Funny: regex → НКА → ДКА → минимизация

Реализация на **чистом Python 3** (без внешних зависимостей, кроме `pytest`
для тестов). Полный конвейер:

```
регулярное выражение (текст)
        │  regex_ast.py   — рекурсивный парсер
        ▼
       AST
        │  thompson.py    — построение по Томпсону
        ▼
   эпсилон-НКА (на каждый токен, затем объединяются)
        │  automata.py    — subset construction
        ▼
      ДКА (полностью определённый, с явной "ловушкой")
        │  minimize.py    — алгоритм Хопкрофта
        ▼
  минимизированный ДКА  →  lexer.py: сканирование текста (maximal munch)
```

## Структура проекта

```
funny_lexer/
├── regex_ast.py     # текстовый regex -> AST (литералы, классы [a-z], |, *, +, ?, (), \escape)
├── thompson.py       # AST -> эпсилон-НКА (конструкция Томпсона)
├── automata.py        # объединение НКА токенов + subset construction -> ДКА (с ловушкой)
├── minimize.py         # минимизация ДКА по алгоритму Хопкрофта
├── lexer.py             # определения токенов языка Funny + сканер (maximal munch)
├── build.py              # CLI: статистика, экспорт table.json, токенизация файла
├── examples/fib.fun      # пример программы на Funny
├── tests/test_lexer.py   # pytest: все обязательные сценарии из задания
└── REPORT.md              # отчёт (см. ниже)
```

## Запуск

Зависимостей для самого лексера нет (стандартная библиотека). Для тестов:

```bash
pip install pytest --break-system-packages   # если pytest ещё не установлен
```

### Собрать автомат и посмотреть статистику

```bash
python3 build.py
```

Выведет количество токенов, размер алфавита, число состояний ДКА до/после
минимизации и выгрузит таблицу переходов минимизированного ДКА в `table.json`
(флаг `--raw-out table_raw.json` дополнительно выгружает ДКА до минимизации
для сравнения).

### Токенизировать файл

```bash
python3 build.py --scan examples/fib.fun
```

Печатает список токенов `(позиция, тип, лексема)`. Если во входном файле
встретился символ, не покрытый ни одним токеном (в том числе любой
non-ASCII символ), сканирование сообщает об ошибке с указанием позиции и
символа, но не падает — лексер пропускает один символ и продолжает разбор
дальше (типичное восстановление после ошибки для лексера).

### Картинка ДКА (для отчёта)

Требует пакет `graphviz` (`pip install graphviz --break-system-packages`) и
системный бинарник `dot` (пакет `graphviz` в apt/pacman/brew).

```bash
python3 draw_dfa.py --token INT                    # маленький ДКА одного токена -> dfa_int.png
python3 draw_dfa.py --token INT --show-trap         # + явно нарисованная ловушка
python3 draw_dfa.py                                 # весь ДКА лексера (минимизированный) -> dfa_full.png
python3 draw_dfa.py --raw --out dfa_full_raw         # версия до минимизации, для сравнения
```

Рёбра с одинаковыми (откуда, куда) объединяются в одну подписанную стрелку
(например `a-z, 0-9, _`), иначе на 98-символьном алфавите граф был бы
нечитаем. Ловушка по умолчанию не рисуется (все "недостающие" переходы
неявно ведут в неё) — показать её явно можно флагом `--show-trap`.
Готовые PNG для отчёта лежат в `report_assets/`.

### Тесты

```bash
python3 -m pytest tests/ -v
```

82 теста, все проходят. Покрывают:
- пустую строку;
- строки только из пробелов/табов/CRLF;
- числа `0`, `00`, `01` и другие (в т.ч. отрицательные примеры с ведущим нулём);
- идентификаторы с `_`;
- все 9 ключевых слов (и то, что их префиксы/расширения — `iffy`, `elsewhere` — остаются `IDENT`);
- все операторы/разделители `()[]{},;` `+ - * / == != <= >= < > =`, включая приоритет двухсимвольных операторов над односимвольными (`==` не read как два `=`);
- однострочные комментарии `//...` (до конца строки, не съедающие `\n`);
- символы вне алфавита (non-ASCII) → явная ловушка → ошибка лексера с восстановлением;
- полную программу на Funny целиком;
- свойства самого ДКА (полнота функции переходов, сток-ловушка, `min ≤ raw`).

## Как использовать в лексере проекта (контрольная точка T0)

`table.json` — самодостаточное описание минимизированного ДКА:
`alphabet`, `start`, `trap`, `states`, `accepting` (состояние → тип токена),
`transitions` (состояние → символ → состояние). Формат специально плоский
(словарь словарей), чтобы его можно было прочитать на любом языке без
Python: загрузить JSON и реализовать тот же цикл maximal-munch, что в
`CombinedLexer.scan` (см. `lexer.py`), либо напрямую импортировать
`lexer.py`/`build_lexer()` как модуль, если проект на Python.

## Дизайн-решения (коротко)

- **Алфавит ДКА** — не все 128 кодов ASCII, а только символы, реально
  встречающиеся хотя бы в одном регулярном выражении токенов (98 символов:
  буквы, цифры, `_`, пробельные, печатные ASCII для тела комментария и
  спецсимволы операторов). Любой символ вне этого множества (включая все
  non-ASCII) по определению ведёт в ловушку — это и есть требуемое
  покрытие «символов вне алфавита».
- **Приоритеты токенов** — порядок в `TOKEN_DEFS` (ключевые слова строго
  раньше `IDENT`). При равной длине совпадения побеждает токен с меньшим
  индексом; при разной длине — как обычно, более длинное совпадение
  (maximal munch), приоритет тут не участвует.
- **WS/COMMENT** помечены `skip=True` и не попадают в поток токенов,
  но участвуют в автомате наравне с остальными.
